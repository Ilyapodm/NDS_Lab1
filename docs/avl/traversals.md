# Обходы AVLTree

## Публичный контракт

Объявления находятся в `include/tree/avl_tree.hpp`, определения — в `include/tree/avl_tree.tpp`. Порядки DFS перечислены в `include/tree/traversal_order.hpp`.

```cpp
template <typename Visitor>
    requires std::invocable<Visitor&, const T&>
void for_each(TraversalOrder order, Visitor&& visitor) const;

template <typename Visitor>
    requires std::invocable<Visitor&, const T&>
void for_each_bfs(Visitor&& visitor) const;
```

Каждый узел посещается ровно один раз. Обработчик получает `const T&`, поэтому обход не копирует значения и не предоставляет изменяемый доступ к ключам. Узлы остаются внутренней деталью дерева.

Для пустого дерева обработчик не вызывается. На дереве из одного узла любой поддерживаемый обход вызывает его один раз. Возвращаемое значение обработчика игнорируется, остановка по `bool` не предусмотрена.

Во время вызова обработчик должен сохранять структуру дерева и порядок его ключей. Вставка, удаление, очистка, присваивание и перемещение этого дерева через другую ссылку нарушают контракт обхода. `const` у метода ограничивает доступ через текущий объект, но не предотвращает изменение через захваченную внешнюю ссылку.

## Почему обработчик шаблонный

`Visitor` может быть лямбдой, функцией или объектом с `operator()`. Его конкретный тип сохраняется при компиляции. Отдельный объект `std::function` и копирование обработчика для обхода не требуются.

`Visitor&&` здесь является forwarding reference, поскольку `Visitor` выводится из аргумента. Она позволяет передавать и именованный объект, и временную лямбду. Внутри метода именованный параметр `visitor` используется как lvalue. DFS передаёт его дальше через `Visitor&`, поэтому все вызовы обращаются к одному объекту и накапливают состояние в нём.

Повторный `std::forward` при каждом посещении не нужен. Обработчик используется многократно как один существующий объект. Некопируемые обработчики поддерживаются, если их можно вызвать как lvalue.

`std::invocable<Visitor&, const T&>` проверяет при компиляции допустимость вызова с константной ссылкой на значение. `std::invoke(visitor, node.value)` выполняет этот вызов и согласуется с ограничением. Он поддерживает обычные функции, лямбды, функциональные объекты и подходящие указатели на члены типа T.

## Шесть DFS-обходов

Буква К обозначает обработку корня текущего поддерева, Л — обход левого поддерева, П — правого. В коде используются латинские K, L и P.

Для дерева ниже результаты получаются следующими.

```text
        4
      /   \
     2     6
    / \   / \
   1   3 5   7
```

| Порядок | Последовательность | Момент обработки узла |
| --- | --- | --- |
| KLP | 4 2 1 3 6 5 7 | перед левым и правым поддеревьями |
| KPL | 4 6 7 5 2 3 1 | перед правым и левым поддеревьями |
| LPK | 1 3 2 5 7 6 4 | после левого и правого поддеревьев |
| LKP | 1 2 3 4 5 6 7 | между левым и правым поддеревьями |
| PLK | 7 5 6 3 1 2 4 | после правого и левого поддеревьев |
| PKL | 7 6 5 4 3 2 1 | между правым и левым поддеревьями |

LKP выдаёт значения в порядке `Compare`. Например, при `std::greater<T>` это убывающий порядок. Обход следует связям уже построенного дерева и сам компаратор не вызывает. Форма AVL меняется при балансировке, поэтому последовательности зависят от текущей формы дерева.

Публичный `for_each` сначала проверяет `order` через `switch`. Некорректное значение, например полученное через `static_cast<TraversalOrder>(99)`, вызывает `std::invalid_argument` до первого посещения, в том числе для пустого дерева. Проверка в начале позволяет рекурсивному методу работать с уже допустимым порядком.

Приватный `traverse_impl(const Node<T>&, TraversalOrder, Visitor&)` получает существующий узел. Наличие корня проверяет публичный метод, а наличие ребёнка проверяется перед рекурсивным вызовом.

Единая реализация выбирает два параметра обхода.

- `left_first` определяет, какое поддерево посещается первым
- Позиция K в выбранном порядке определяет, когда вызывается обработчик

`first` и `second` имеют тип `const node_link&`. Они ссылаются на поля владения внутри узла, позволяют проверить отсутствие ребёнка и не передают владение. Копировать `unique_ptr` для этого не требуется.

Рекурсия повторяет структуру дерева и сохраняет общий механизм для всех шести порядков. Для AVL глубина ограничена O(log n), поэтому отдельный стек узлов здесь не нужен.

## BFS через Queue

BFS посещает уровни сверху вниз, внутри уровня — слева направо. Для дерева из примера результат равен `4 2 6 1 3 5 7`.

Алгоритм помещает корень в собственную `Queue` из `include/containers/queue.hpp`. Пока очередь не пуста, он извлекает первый узел, обрабатывает значение и добавляет существующих детей, сначала левого, затем правого. FIFO сохраняет очередь ожидания, поэтому дети текущего уровня обрабатываются после всех уже поставленных узлов.

Для дерева из примера первые состояния очереди имеют такой вид.

```text
[4]
[2, 6]          после обработки 4
[6, 1, 3]       после обработки 2
[1, 3, 5, 7]    после обработки 6
```

Одновременно в очереди могут находиться остаток текущего уровня и часть следующего. Каждый узел добавляется и извлекается один раз.

### Владение и ссылки

Тип очереди имеет вид `Queue<std::reference_wrapper<const Node<T>>>`.

- AVLTree владеет корнем, а каждый узел дерева владеет детьми через `unique_ptr`
- Queue владеет своей отдельной цепочкой записей через `unique_ptr`
- Запись очереди содержит невладеющую ссылку на существующий узел дерева

`std::reference_wrapper` — копируемый объект, хранящий ссылку. Обычная ссылка `const Node<T>&` не подходит в качестве T нашей очереди, реализация которой перемещает хранимые значения. Обёртка позволяет передавать ссылку как значение, сохраняя единственного владельца узла в дереве.

`std::cref(*root_)` создаёт обёртку с константной ссылкой на корень. Аналогично добавляются дети. Копирование и перемещение обёрток не копирует узлы и их значения.

Ключевой участок выглядит так.

```cpp
const Node<T>& node = pending.front().get();
pending.pop();
std::invoke(visitor, node.value);
```

`front()` возвращает ссылку на обёртку внутри первой записи очереди. `get()` извлекает из неё ссылку на узел дерева, и именно эта ссылка сохраняется в `node`. После `pop()` запись и обёртка уничтожаются, но узел остаётся во владении дерева. Поэтому `node` остаётся действительной.

Гарантию времени жизни обеспечивает контракт о сохранении структуры дерева во время обхода. Если обработчик сохраняет ссылку на значение после завершения обхода, он должен учитывать дальнейшее удаление этого элемента, очистку или уничтожение владеющего дерева.

## Исключения и стоимость

Исключение обработчика немедленно прерывает обход и передаётся вызывающему коду. BFS также может завершиться исключением при выделении памяти для записи Queue. Оба метода поэтому допускают исключения.

При выходе из BFS локальная очередь освобождает записи итеративно, избегая рекурсивного уничтожения длинной цепочки. Дерево сохраняет свои узлы, размер и высоты. Уже выполненные действия обработчика, например добавление значений во внешний вектор, сохраняются. При ошибке добавления детей текущий узел уже мог быть обработан.

| Обход | Время | Дополнительная память |
| --- | --- | --- |
| DFS | O(n) | O(h) стека, для AVL O(log n) |
| BFS | O(n) | O(w), где w — максимальная ширина дерева |

Оценки исключают стоимость обработчика. Для BFS очередь может содержать части двух уровней, что сохраняет оценку O(w). В широком дереве w может быть O(n). Пустое дерево обрабатывается за O(1).

## Пример использования

```cpp
AVLTree<int> tree;
tree.insert(4);
tree.insert(2);
tree.insert(6);

std::vector<int> sorted;
tree.for_each(TraversalOrder::LKP, [&](const int& value) {
    sorted.push_back(value);
});

std::vector<int> levels;
tree.for_each_bfs([&](const int& value) {
    levels.push_back(value);
});
```

Для примера нужен заголовок `<vector>`. После вызовов `sorted` содержит `2, 4, 6`, а `levels` — `4, 2, 6`.

## Проверка всех значений с ранней остановкой

`all_of` принимает обработчик с ограничением `std::predicate<Predicate&, const T&>`. Он проверяет значения в порядке LKP и возвращает false при первой неудаче. Пустое дерево возвращает true. В Set этот метод проверяет включение, вызывая contains другого множества.

Приватный all_of_impl получает существующий узел через `const Node<T>&`, поэтому предикат фактически получает константную ссылку. Концепт проверяет допустимость вызова, а константная ссылка на узел обеспечивает константность переданного значения.

Проверка левого поддерева, текущего значения и правого поддерева соединена обычным `&&`. Если одна часть возвращает false, оставшиеся рекурсивные вызовы пропускаются. Результат возвращается вверх обычными возвратами из функций. Исключения для остановки не используются.

В худшем случае посещаются все n узлов, стек для AVL занимает O(log n). Предикат должен соблюдать тот же контракт сохранения дерева, что и обработчики других обходов.
