# map, where и reduce для AVLTree

## Общая архитектура

Методы объявлены в `include/tree/avl_tree.hpp` и определены в `include/tree/avl_tree.tpp`. Они используют существующий `for_each`. Передача владения узлами и балансировка остаются внутри операций дерева.

Обработчики получают `const T&`. Исходное дерево сохраняет свои значения, связи, высоты и размер при соблюдении [контракта обходов](avl_traversals.md). В частности, обработчик должен сохранять структуру дерева и порядок ключей, в том числе при доступе через внешнюю ссылку.

`map` и `where` создают независимое дерево типа `AVLTree<T, Compare>` с копией исходного экземпляра компаратора. Это сохраняет настройки компаратора с состоянием, например направление сортировки. Каждый узел результата имеет собственного владельца.

Все три метода вызывают обработчик в определённом порядке. Для `map` и `where` это LKP, для `reduce` порядок выбирает вызывающий код.

## map

```cpp
template <typename Mapper>
    requires std::invocable<Mapper&, const T&>
          && std::same_as<std::invoke_result_t<Mapper&, const T&>, T>
AVLTree<T, Compare> map(Mapper&& mapper) const;
```

`std::invocable` проверяет возможность вызвать обработчик с `const T&`. `std::invoke_result_t` определяет тип результата такого вызова, а `std::same_as` требует точного совпадения с T. Текущий контракт преобразует значения в пределах одного типа. Возврат ссылки на T также не удовлетворяет этому ограничению.

Алгоритм создаёт пустой результат, посещает каждый исходный элемент и передаёт преобразованное значение в `result.insert(...)`. Произвольное преобразование может поменять порядок ключей, поэтому вставка заново устанавливает положение элемента и поддерживает AVL-баланс.

Эквивалентность определяется компаратором результата. Если несколько исходных элементов преобразованы в эквивалентные значения, сохраняется первое успешно вставленное значение в порядке обработки LKP. Размер результата может уменьшиться.

```cpp
auto negative = tree.map([](const int& value) {
    return -value;
});

auto remainders = tree.map([](const int& value) {
    return value % 3;
});
```

### Вставка результата через T&&

Публичные `insert(const T&)` и `insert(T&&)` имеют соответствующие перегрузки `insert_impl`. Значение, возвращённое mapper по значению, попадает в перегрузку с T&&.

`std::move(value)` разрешает перемещение объекта. При передаче аргумента в следующий рекурсивный вызов сама привязка T&& ничего не перемещает. Сравнения выполняются с исходным значением. Реальное перемещение происходит при создании узла после обнаружения пустой связи.

Если найден дубликат, новый узел не создаётся, а переданное значение не перемещается. Существующий конструктор `Node(T)` принимает значение по значению и затем перемещает его в поле узла, поэтому возможны несколько перемещений. Для обычного перемещаемого T копирование результата mapper не требуется.

При исключении из компаратора, выделения памяти или конструктора значения дерево назначения сохраняет прежнее состояние. Если исключение возникло уже во время перемещения T, переданный объект может оказаться изменённым. При вызове из map этим объектом является результат mapper.

### Почему выбран LKP

LKP обрабатывает исходные значения в порядке Compare и использует O(log n) стека для AVL. Сортированный поток вставок может требовать вращений, которые выполняет обычный insert.

Обсуждался BFS. Для преобразования, сохраняющего строгий порядок и уникальность значений, вставка в BFS-порядке восстанавливает исходную форму AVL без вращений. Общий контракт map допускает изменение порядка и появление дубликатов, поэтому эта гарантия относится к ограниченному набору преобразований.

BFS требует O(w) памяти очереди, вплоть до O(n). Наша связная Queue также выделяет отдельную запись для каждого добавленного узла. Поиск места вставки остаётся O(log n) даже при отсутствии вращений. В текущей реализации выбран LKP с малым расходом памяти и определённым порядком обработки. Реальный выигрыш BFS требует измерений.

## where

```cpp
template <typename Predicate>
    requires std::predicate<Predicate&, const T&>
AVLTree<T, Compare> where(Predicate&& predicate) const;
```

Предикат проверяет очередное значение. Если результат проверки истинен, значение копируется в новое дерево через `insert(const T&)`. Исходные элементы остаются доступны владельцу исходного дерева, а результат получает независимые узлы.

Для вызова where требуется возможность скопировать T в узел. Предикат должен соответствовать требованиям `std::predicate`, включая стабильный результат для одинакового аргумента и сохранение проверяемого значения. Компилятор проверяет допустимость вызова и результата, а семантические требования соблюдает вызывающий код.

```cpp
auto even = tree.where([](const int& value) {
    return value % 2 == 0;
});
```

Для пустого дерева предикат не вызывается. Если все проверки ложны, возвращается пустое дерево. Если все истинны, результат содержит все значения исходного дерева. Форма результата определяется последовательностью вставок и может отличаться от исходной.

## reduce

```cpp
template <typename Accumulator, typename Reducer>
Accumulator reduce(
    Accumulator initial,
    Reducer&& reducer,
    TraversalOrder order = TraversalOrder::LKP
) const;
```

Начальный аккумулятор передаётся по значению. Передача lvalue копирует его, а передача временного объекта или `std::move` позволяет перемещение. Тип аккумулятора может отличаться от T.

На каждом шаге выполняется следующая операция.

```cpp
initial = std::invoke(reducer, std::move(initial), value);
```

Редуктор получает текущий аккумулятор и `const T&`, возвращает следующее состояние. Оно присваивается в локальный `initial`. Результат должен быть присваиваемым аккумулятору, а сам аккумулятор должен допускать передачу и возврат в рамках этой реализации.

Передача аккумулятора через `std::move` позволяет редуктору принимать его по значению с перемещением. Так поддерживается и некопируемый аккумулятор, например `std::unique_ptr`. Редуктор, принимающий только изменяемую lvalue-ссылку на аккумулятор, не соответствует текущему способу вызова.

```cpp
int sum = tree.reduce(0, [](int accumulator, const int& value) {
    return accumulator + value;
});

auto join = [](std::string text, const int& value) {
    return text + std::to_string(value);
};

std::string sorted = tree.reduce(std::string{}, join);
std::string preorder = tree.reduce(std::string{}, join, TraversalOrder::KLP);
```

Для строкового примера требуется `<string>`. Порядок важен для операций вроде конкатенации. По умолчанию LKP задаёт порядок Compare. Доступны шесть DFS-порядков из TraversalOrder.

Пустое дерево возвращает начальный аккумулятор без вызова редуктора. Некорректный order вызывает `std::invalid_argument` через for_each, в том числе на пустом дереве.

## Передача обработчиков и время жизни

Параметры `Mapper&&`, `Predicate&&` и `Reducer&&` являются forwarding references. Они принимают именованные и временные обработчики. Внутри метода обработчик используется как lvalue и вызывается через `std::invoke`.

Внутренняя лямбда захватывает локальные объекты через `[&]`. Это обычные ссылки на результат, аккумулятор и обработчик. `for_each` выполняет обход синхронно и не сохраняет лямбду после возврата, поэтому эти ссылки действуют всё время её использования. Копирование обработчика для каждого элемента не требуется.

`std::reference_wrapper` в этих операциях не нужен, поскольку ссылки передаются непосредственно через вызовы функций. Обёртка применяется в BFS, где ссылку необходимо хранить как значение в Queue.

## Исключения и сложность

Исключения обработчиков, компаратора, копирования и перемещения значений, а также выделения памяти передаются вызывающему коду. Если map или where завершается исключением, локальное дерево результата автоматически освобождает уже созданные узлы через unique_ptr. Исключение при копировании компаратора также прерывает создание результата.

При ошибке reduce локальный аккумулятор уничтожается. Если вызывающий код заранее переместил в initial свой объект, восстановление этого внешнего объекта не предусмотрено. Действия обработчика над внешними объектами также сохраняются. Исходное дерево сохраняет состояние при соблюдении контракта обработчика.

Пусть n — число исходных элементов, а k — число узлов результата. При O(1) стоимости обработки одного элемента и сравнения оценки имеют следующий вид.

| Операция | Время | Память результата | Дополнительный стек |
| --- | --- | --- | --- |
| map | O(n log(n + 1)) в худшем случае | O(k) | O(log(n + 1)) |
| where | O(n + k log(k + 1)) | O(k) | O(log(n + 1)) |
| reduce | O(n) | зависит от аккумулятора | O(log(n + 1)) |

Фактическая стоимость обработчиков, значений и компаратора учитывается отдельно. Например, конкатенация растущей строки может давать суммарное время больше O(n). Для пустого дерева накладные расходы обхода равны O(1).
