# Set на основе AVLTree

## Устройство и подключение

Set<T, Compare> хранит уникальные ключи в AVLTree<T, Compare>. Закрытое поле tree_ владеет деревом, а дерево — узлами через unique_ptr. Базовые операции Set делегируются AVLTree, поэтому поиск, балансировка, высоты и управление памятью реализованы в одном месте.

`include/set/set.hpp` содержит объявления, `include/set/set.tpp` — определения шаблонов. Для использования подключается `set/set.hpp`. CMake-цель `nds_lab1_set` транзитивно подключает `nds_lab1_avl_tree`, путь к заголовкам и требование C++20. Другой проект может подключить лабораторную через add_subdirectory и связать свою цель с nds_lab1_set.

```cpp
#include "set/set.hpp"

Set<int> values;
values.insert(3);
values.insert(1);
values.insert(3);
```

После этих операций множество содержит ключи 1 и 3. Конструктор по умолчанию создаёт пустое множество. Конструктор с Compare принимает выбранный экземпляр компаратора, включая его состояние.

## Уникальность и сравнение ключей

Compare должен задавать строгий слабый порядок. Два значения эквивалентны для множества, если обе проверки comp(a, b) и comp(b, a) возвращают false.

Например, Student сравнивается по id. Студенты с одинаковым id эквивалентны для Set, даже если их имена и оценки различаются. В узле хранится полное значение Student.

Повторный insert возвращает false и сохраняет уже хранимую запись. Операции равенства Set также сравнивают принадлежность ключей через Compare. Поэтому множества с одинаковыми id студентов равны, даже когда прочие поля записей различаются. Форма внутренних деревьев на равенство не влияет.

Для бинарных операций экземпляры Compare обоих операндов должны задавать одинаковый порядок и эквивалентность ключей. Совпадение самого типа Compare этого не гарантирует, если направление или правила сравнения зависят от состояния. Это предусловие вызывающего кода, автоматически оно не проверяется.

Результаты union_with, intersection_with и difference всегда получают экземпляр компаратора левого операнда. Его дополнительные данные сохраняются даже при одинаковом порядке сравнения обоих компараторов.

## Базовый API и доступ к значениям

| Метод | Поведение |
| --- | --- |
| insert(const T&) | копирует новый элемент в дерево, возвращает успех вставки |
| insert(T&&) | перемещает новый элемент при создании узла, возвращает успех вставки |
| erase(const T&) | удаляет эквивалентный ключ, возвращает успех удаления |
| contains(const T&) const | проверяет наличие эквивалентного ключа |
| find(const T&) const | возвращает необязательную константную ссылку на хранимое значение |
| size() const noexcept | возвращает число элементов |
| empty() const noexcept | проверяет отсутствие элементов |
| clear() noexcept | уничтожает все элементы |

find_result совпадает с типом результата AVLTree, то есть optional<reference_wrapper<const T>>. При отсутствии ключа возвращается nullopt. get() у обёртки даёт константную ссылку на полное хранимое значение.

```cpp
const auto found = values.find(3);
if (found) {
    const int& value = found->get();
}
```

Такая ссылка сохраняется при вращениях дерева. Она становится недействительной при удалении соответствующего узла, очистке, уничтожении владеющего контейнера или замене его прежнего дерева присваиванием. При передаче узлов перемещением ссылка продолжает относиться к тому же узлу у нового владельца.

При вставке через T&& сравнения выполняются до перемещения. Если ключ уже существует, переданный объект сохраняет значение. Подробнее владение и вставка разобраны в [архитектуре AVLTree](avl/README.md) и [функциональных операциях](avl/functional_operations.md).

## Объединение

A.union_with(B) возвращает ключи, принадлежащие A или B.

Сначала выбирается большее множество и глубоко копируется целиком. При одинаковых размерах копируется левое. Затем по меньшему выполняется inorder-обход с добавлением его элементов.

Если скопировано левое дерево, insert правых элементов сохраняет уже имеющиеся левые значения. Если большее дерево правое, его узлы копируются с выбранным левым компаратором. Для этого приватный конструктор Set использует AVLTree(const AVLTree& other, Compare comp). Форма скопированного дерева остаётся допустимой благодаря предусловию одинакового порядка.

При последующем обходе левого множества каждое его значение сначала удаляет эквивалентный ключ из результата, затем вставляется само. Так при совпадении ключей сохраняется полная запись из левого операнда. Дополнительный erase необходим, поскольку insert существующего ключа сохраняет старое значение.

Все изменения происходят в новом дереве результата.

## Пересечение

A.intersection_with(B) возвращает ключи, принадлежащие обоим множествам.

Результат создаётся пустым с левым компаратором. Обходится меньшее множество, при равенстве размеров — левое.

Если обходится левое, contains правого проверяет принадлежность, и подходящее левое значение вставляется в результат. Если обходится правое, find левого одновременно проверяет ключ и получает полную левую запись для вставки.

Таким образом, выбор меньшего множества сокращает число поисков, сохраняя правило выбора значения из левого операнда.

Объединение и пересечение коммутативны по набору эквивалентных ключей. При разных данных под одинаковыми ключами полные записи результата зависят от порядка операндов.

## Разность

A.difference(B) возвращает элементы A, чьих ключей нет в B.

Алгоритм проходит по левому множеству, проверяет каждый ключ через B.contains и вставляет отсутствующие в новое дерево с левым компаратором. Здесь направление операции определяет и источник значений, и множество, которое требуется обойти.

## Подмножество и равенство

A.is_subset_of(B) сначала сравнивает размеры. Если A больше B, результат сразу равен false. Иначе AVLTree::all_of проверяет для каждого значения A условие B.contains(value).

all_of выполняет inorder с коротким замыканием логического &&. При первом отсутствующем ключе дальнейшие вызовы предиката и обход оставшихся ветвей прекращаются. false возвращается вверх по рекурсивным вызовам обычным возвратом. Для пустого дерева all_of возвращает true.

Оператор == проверяет равенство размеров, затем is_subset_of. При одинаковом числе уникальных ключей включения в одну сторону достаточно для равенства. Оператор != возвращает отрицание ==.

## map, where и reduce

Set делегирует эти операции AVLTree. Контракты обработчиков, перемещение результатов, исключения и подробные примеры приведены в [функциональных операциях дерева](avl/functional_operations.md).

map и where возвращают новый Set того же типа T с копией компаратора источника. Приватный конструктор принимает готовое дерево перемещением.

std::forward передаёт обработчик в дерево, сохраняя способ передачи аргумента. Дерево затем многократно вызывает один объект обработчика как lvalue.

При коллизии map остаётся первый результат в порядке исходного Compare. Например, если студентам с id 1 и 2 присвоить id 10, при стандартном сравнении сохранятся остальные поля исходного студента с id 1. Убывающий компаратор выберет студента с id 2.

Set::reduce принимает initial и reducer. Он всегда использует внутренний inorder, поэтому для конкатенации результат определяется Compare. Для дерева порядок свёртки можно выбрать.

## Обход и обработчики

for_each(visitor) вызывает обработчик в порядке Compare через внутренний LKP-обход. Каждый элемент посещается один раз, аргумент имеет тип const T&, возвращаемое обработчиком значение игнорируется.

Во время обработки пользовательские функции должны сохранять структуру исходного контейнера и порядок его ключей, в том числе при доступе через другую ссылку. Исключение обработчика прерывает выполнение и передаётся вызывающему коду. Уже выполненные действия над внешними объектами сохраняются.

## Сериализация и десериализация

serialize делегирует запись дереву. Статический deserialize принимает строку и необязательный Compare, восстанавливает отдельное дерево и передаёт его новому Set через приватный конструктор.

Формат, требования к T, Student, валидация и гарантии при ошибках общие с AVLTree и описаны в [сериализации](serialization.md). Равенство Set определяется ключами, поэтому равные множества могут иметь разные строки при разных формах деревьев или остальных полях записей.

## Копирование, перемещение и исключения

Специальные методы Set генерируются компилятором и вызывают методы единственного поля tree_. Правила независимого копирования, состояния после перемещения и требования к Compare наследуются от [AVLTree](avl/README.md#копирование-и-перемещение).

Объединение, пересечение и разность строят отдельный результат. При исключении операнды сохраняются, частичные узлы результата освобождаются. Это относится и к ситуации, когда замена правой записи в объединении уже выполнила erase, а следующий insert завершился ошибкой.

Гарантии map, where и reduce определяются соответствующими операциями дерева и контрактом обработчика.

## Граничные случаи

Пустое множество является подмножеством любого. Объединение с пустым возвращает независимую копию содержимого второго операнда с компаратором левого. Пересечение с пустым даёт пустое множество.

Разность A с пустым возвращает содержимое A, а разность пустого с A пуста. Объединение и пересечение A с самим собой сохраняют его значения в новом контейнере, разность A с собой пуста.

Пустые map и where создают пустой результат без вызова обработчика. Пустой reduce возвращает начальное значение.

## Сложность

Пусть n — размер левого множества, m — правого, s = min(n, m), M = max(n, m), r — размер результата. Оценки даны при постоянной стоимости сравнения и операций с одним значением. Накладные расходы для полностью пустых входов постоянны.

| Операция | Время в худшем случае |
| --- | --- |
| union_with | O(M + s log(n + m + 1)) |
| intersection_with | O(s log(M + 1) + r log(r + 1)) |
| difference | O(n log(m + 1) + r log(r + 1)) |
| is_subset_of | O(n log(m + 1)), при n > m — O(1) |
| ==, != | O(n log(m + 1)), при разных размерах — O(1) |

Оценки базовых операций приведены в [AVLTree](avl/README.md#сложность-и-проверки), map/where/reduce — в [функциональных операциях](avl/functional_operations.md#исключения-и-сложность).

Новые множества занимают O(r) памяти под узлы результата. Обходы и рекурсивные операции AVL дополнительно используют стек логарифмической глубины. Память и время пользовательских обработчиков, элементов, компараторов и аккумулятора учитываются отдельно.

## Проверки

В tests/test_set.cpp проверены базовые операции, независимость копии, обе ветви выбора размера для объединения и пересечения, пустые и непересекающиеся множества, операции с собой, включение и равенство. Тесты со Student проверяют полные записи при совпадении ключей, а счётчики компараторов — сохранение именно левого экземпляра.

Для функциональных операций проверены преобразование, коллизии в возрастающем и убывающем порядке, фильтрация, порядок свёртки, некопируемый аккумулятор, пустой вход и исключения. Ранняя остановка all_of отдельно проверена в тестах AVLTree.

Для сериализации проверены пустое множество, один элемент, сохранение формы и независимость результата, специальные символы в строках, полные поля Student, ошибочный вход и переданный компаратор.
