# Сериализация AVLTree, Set и Student

## Подключение и API

Для чисел и строк достаточно заголовка `tree/avl_tree.hpp`. Для Student также подключается `models/student_streams.hpp`. Операторы находятся в отдельном заголовке и объявлены inline, поэтому дополнительная компилируемая библиотека не требуется.

```cpp
#include "tree/avl_tree.hpp"
#include "models/student_streams.hpp"

AVLTree<Student> tree;
tree.insert(Student{17, "Ivan", "Petrov", 2005, 4.75});

std::string data = tree.serialize();
auto restored = AVLTree<Student>::deserialize(data);
```

`serialize() const` возвращает строку. Статический `deserialize(const std::string&, Compare comp = Compare{})` создаёт новое дерево. Если компаратор имеет состояние, вызывающий код передаёт подходящий экземпляр вторым аргументом. Строка хранит структуру и значения, а состояние компаратора задаётся отдельно.

При успешном восстановлении сохраняются значения и форма дерева. Высоты и размер вычисляются заново. Результат владеет собственными узлами, поэтому его изменение не затрагивает исходное дерево.

Распределение ответственности по файлам приведено ниже.

| Файл | Ответственность |
| --- | --- |
| `models/student.hpp` | поля, конструкторы и сравнение студентов |
| `models/student_streams.hpp` | текстовое представление одного студента |
| `serialization/serialization_utils.hpp` | ввод и вывод одного значения, проверка границ |
| `tree/avl_tree.tpp` | запись структуры и восстановление с проверкой инвариантов |
| `tests/test_serialization.cpp` | проверки формата, восстановления и ошибок |

## Делегирование в Set

Set предоставляет serialize и статический deserialize с теми же входными данными и правилом выбора компаратора. Он использует сериализацию внутреннего AVLTree. Готовое проверенное дерево передаётся новому Set через перемещение без клонирования узлов.

Формат сохраняет полные значения и форму внутреннего дерева. Равенство множеств по ключам допускает разные сериализованные строки из-за различий формы и остальных полей записей. Сохранение значения и формы при восстановлении проверяется отдельно от равенства Set.

## Формат и работа потоков

Запись использует фиксированный preorder КЛП. Каждая пустая связь обозначается отдельным маркером `#`. Например, дерево с корнем 8 и детьми 4 и 12 записывается как `8 4 # # 12 # #`. Пустое дерево записывается как `#`. Маркеры позволяют восстановить исходную форму.

Правило записи одного поддерева имеет два варианта.

```text
пустое поддерево       #
непустое поддерево     значение левое_поддерево правое_поддерево
```

Для n узлов записывается n значений и n + 1 пустых связей. Значение пользовательского типа может содержать несколько полей, поэтому количество слов, разделённых пробелами, зависит от T.

Сериализатор разделяет записи одиночными пробелами и удаляет последний служебный пробел. Десериализатор допускает ведущие, завершающие и повторяющиеся пробельные символы между записями.

Потоки дерева настроены на `std::locale::classic()`, поэтому числа используют десятичную точку независимо от глобальной локали.

Помощники в `serialization/serialization_utils.hpp` записывают и читают одно значение. Строки всегда заключены в кавычки через `std::quoted`, которое экранирует кавычки и обратные слеши. Пробелы и переводы строк внутри кавычек сохраняются. Строковое значение `"#"` отличается от маркера `#`.

Для вещественных типов используется `max_digits10`, чтобы восстановить исходное значение без потери точности при текстовом преобразовании. Бесконечности и NaN отклоняются.

После значения или маркера допустимы пробел либо конец входа. Поэтому `12abc` и `#abc` ошибочны. После полной структуры допустимы только пробельные символы. Пустая строка, недостающие дети и лишние записи отклоняются.

Для пользовательского типа требуются согласованные операторы вывода и ввода. Оператор ввода должен прочитать ровно одно значение и сообщить об ошибке через состояние потока. Текст значения должен иметь однозначные границы и начинаться с символа, отличного от зарезервированного маркера `#`. Строки получают такое представление автоматически. Десериализация использует `T value{}`, поэтому требует конструктор по умолчанию, а затем возможность перенести значение в узел.

## Восстановление структуры и проверка AVL

Рекурсивный serialize_impl получает `const node_link&`. Он проверяет пустую связь, записывает значение и затем оба поддерева. Обычный for_each пропускает пустые связи и поэтому не передаёт всех данных о форме.

Рекурсивный deserialize_impl возвращает владеющий `unique_ptr`. Узлы соединяются напрямую. insert здесь не вызывается, поскольку вращения могли бы изменить заданную входом структуру.

Например, чтение `8 4 # # 12 # #` проходит следующим образом.

1. Читается 8 и создаётся корень
2. Для его левой связи читается 4
3. Два маркера завершают детей узла 4, его высота становится равной 1
4. Для правой связи корня читается 12, затем два его пустых ребёнка
5. После завершения обоих детей высота корня становится равной 2
6. Проверяется отсутствие данных после полного дерева

Нижняя и верхняя границы передаются как `optional<reference_wrapper<const T>>`. Это необязательные ссылки на значения предков. Они позволяют проверять ограничения всех предков, сохраняя единственное владение узлами. Родитель остаётся живым до завершения чтения потомков.

`std::nullopt` означает отсутствие границы. `std::cref(node->value)` создаёт константную ссылку-обёртку на значение текущего узла. Для левого ребёнка она становится верхней границей, для правого — нижней. Вызов `get()` возвращает само значение по ссылке. Перемещение владеющего unique_ptr сохраняет адрес узла.

Например, узел 10 в правой ветви узла 4 всё равно нарушает BST, если сам узел 4 находится слева от корня 8. Переданная от корня верхняя граница обнаруживает это нарушение.

Сравнение с границами выполняется через Compare. Нарушение порядка и эквивалентные ключи отклоняются. После завершения детей вычисляется высота узла и проверяется разность высот. size_ восстанавливается по числу созданных узлов.

Вход ещё не является проверенным AVL, поэтому перед рекурсивным чтением узла ограничивается глубина. AVL высоты h имеет не менее 2^(h/2) − 1 узлов. Удвоенное число бит size_t даёт безопасную верхнюю границу высоты дерева с представимым размером. Проверка отклоняет длинные ошибочные цепочки до переполнения стека.

Корень имеет глубину 0. Новый непустой узел разрешён, пока глубина меньше `2 * std::numeric_limits<std::size_t>::digits`. Пустые связи распознаются до проверки глубины. На системе с 64 значащими битами size_t предел составляет 128 уровней непустых узлов. Проверка баланса каждого узла остаётся обязательной даже в пределах этой глубины.

## Student и его текстовый формат

Student содержит id, first_name, last_name, birth_year и average_score. Поля доступны напрямую. operator< сравнивает id, operator== сравнивает все поля. Студенты с одинаковым id эквивалентны для дерева.

Потоковая запись имеет вид `17 "Ivan" "Petrov" 2005 4.75`. Имена обязательно заключаются в кавычки. id должен быть положительным, оценка — конечной. Ограничения на диапазон года и шкалу оценок не вводились. Объект по умолчанию служит заготовкой для чтения, его id равен нулю, поэтому запись такого объекта завершается ошибкой.

Модель находится в `models/student.hpp`, потоковые операторы — в `models/student_streams.hpp`. Они работают с консольными, файловыми и строковыми потоками.

Разделение файлов отделяет данные и сравнение от выбранного текстового формата. Типы std::istream и std::ostream сами по себе уже подходят для различных источников и получателей данных. inline позволяет включать заголовок с определениями операторов в несколько единиц трансляции.

Вывод строит промежуточную запись с локалью предоставленного потока и точностью double max_digits10. Настройки точности и локали самого внешнего потока сохраняются. При сериализации дерева локаль уже установлена в classic.

Ввод сначала полностью разбирает временный Student и лишь затем присваивает его получателю. Если поле ошибочно, устанавливается failbit, а получатель сохраняет прежние данные. При включённых исключениях потока установка failbit может выбросить ios_base::failure.

Отдельный operator>> читает ровно пять полей студента и оставляет последующие записи в потоке. Проверка конца всего входа выполняется на уровне дерева после завершения его структуры. Это позволяет одному потоку последовательно содержать несколько студентов и маркеры их детей.

За пределами сериализации дерева локаль задаёт владелец потока. Для согласованного чтения и записи отдельного Student следует использовать одинаковую локаль.

## Состояния потоков

`std::ws` пропускает пробельные символы, `peek()` смотрит следующий символ без извлечения, `get()` извлекает маркер. Проверка состояния после `>>` обнаруживает неверное значение и выход числа за диапазон типа.

Успешное чтение последнего числового поля может установить eofbit. Сам по себе eofbit означает достижение конца входа. failbit обозначает неудачу операции чтения. Поэтому проверки конца значения учитывают уже установленный eofbit, а после полной структуры допускается окончание потока.

std::quoted способен прочитать и обычное слово без кавычек. Перед его вызовом код явно проверяет открывающую кавычку, обеспечивая обязательный формат строк.

При ошибке поля operator>> для Student устанавливает failbit. Затем read_value<Student> видит неудачный ввод и выбрасывает std::invalid_argument. Так потоковый контракт модели согласуется с контрактом метода deserialize.

## Ошибки и стоимость

Некорректный формат, порядок, баланс и неподдерживаемые числовые значения приводят к std::invalid_argument. Ошибки выделения памяти и исключения пользовательских операций передаются вызывающему коду.

При неудаче чтения частично созданные узлы освобождаются через unique_ptr. Существующие деревья сохраняются, поскольку весь результат строится отдельно. Например, в присваивании `tree = AVLTree<int>::deserialize(data)` получатель меняется только после успешного восстановления.

Примеры отклоняемых данных приведены ниже.

| Вход для AVLTree<int> | Причина |
| --- | --- |
| пустая строка | отсутствует даже маркер пустого корня |
| `8 #` | отсутствует правая связь корня |
| `# #` | лишняя запись после пустого дерева |
| `8abc # #` | неверная граница числового значения |
| `8 8 # # #` | эквивалентный ключ |
| `8 4 # 10 # # #` | нарушение ограничения от предка |
| `1 # 2 # 3 # #` | допустимый BST с нарушенным AVL-балансом |

Сериализация проверяет состояние выходного потока после записи значений и после завершения всей структуры, включая разделители и маркеры.

Время работы составляет O(n + L) при постоянной стоимости сравнения и обработки одного символа, где L — длина текста. Дополнительный стек корректного AVL занимает O(log n). Строка результата занимает O(L), восстановленные узлы — O(n), без учёта внутренней памяти значений T.

## Тесты

Обёртки Set проверяются в tests/test_set.cpp на пустом множестве, одном элементе, строках, полных записях Student, неверном входе и выбранном компараторе.

В test_serialization.cpp проверяются форма и инварианты дерева, пустое дерево, один узел, строки со специальными символами, точность double, пользовательский компаратор и полные записи студентов. Отдельно проверяются повреждённый формат, дубликаты, неверный BST-порядок, неверный баланс, чрезмерная глубина и сохранение получателя после ошибки.

После настройки проекта тесты можно собрать и запустить следующими командами.

```sh
cmake --build build --target tests
ctest --test-dir build --output-on-failure
```
